## Problemas resolvidos

### 1. SWC/SIGBUS no WSL
O compilador Rust do Next.js (SWC) crasha com Bus Error no WSL Ubuntu-24.04.

**Solução aplicada:**
- Renomeado `node_modules/@next/swc-linux-x64-gnu/next-swc.linux-x64-gnu.node` → `.node.bak`
- Renomeado `node_modules/@next/swc-linux-x64-musl/next-swc.linux-x64-musl.node` → `.node.bak`
- Criado `.babelrc` com `{"presets": ["next/babel"]}` para usar Babel como fallback
- Removido `next/font/google` do `app/layout.tsx` (requer SWC) — substituído por `<link>` do Google Fonts

**Atenção:** Se rodar `npm install` ou atualizar o Next.js, os binários `.bak` podem ser sobrescritos e o problema volta. Repetir o procedimento:
```bash
mv node_modules/@next/swc-linux-x64-gnu/next-swc.linux-x64-gnu.node{,.bak}
mv node_modules/@next/swc-linux-x64-musl/next-swc.linux-x64-musl.node{,.bak}
```

### 2. Hydration Error no layout protegido
O `useAuthStore` lê o `localStorage` (só disponível no cliente), causando mismatch entre SSR e CSR.

**Solução:** Adicionado estado `mounted` no `app/(app)/layout.tsx` — renderiza spinner até o componente montar no cliente.

### 3. `categories.map is not a function`
A API retornava dados mas o estado não era array quando vazio.

**Solução:** Guards `Array.isArray()` ao popular o estado no dashboard:
```ts
setCategories(Array.isArray(c.data) ? c.data : []);
setEvolution(Array.isArray(e.data) ? e.data : []);
```

## Observações técnicas

- O `package.json` do frontend tem o script dev com `WATCHPACK_POLLING=true` para funcionar no WSL
- O axios interceptor lê o token em `localStorage` na chave `finance-os-auth` → `state.accessToken`
- Em caso de 401, o interceptor limpa o storage e redireciona para `/login`
- Cores Tailwind customizadas: `primary` (sky blue), `success` (green), `warning` (amber), `danger` (red)
